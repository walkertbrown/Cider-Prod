## Build step 1: the tap page, end to end
What the boss's account shows: three bio-mode networks (Instagram, TikTok,
YouTube), and posts that each name their own site in the text
(puzzlepress..., sizecurve...). So each post gets its own destination.

- After sign-in: a sign-in cookie for the owner only (random id → account in
  KV, 30 days; HttpOnly, Secure). Visitors get no cookie. Then /me.
- Posts are copied from Buffer (sent, newest 50: text, link, thumbnail,
  YouTube/TikTok title) when /me is opened and the copy is older than six
  hours. Never on a public page view. The access token is refreshed when it
  is within a minute of expiring, and the new refresh token is kept at once.
- Each post's destination defaults to the first web address in its text.
  The owner can change it, or set one for all.
- /u/<name>: the public bio page. One tile per post (thumbnail, title or
  first line, network), and each tile goes to /p/<post>. A skip link goes to
  the main destination.
- /p/<post>: counts, then 302s to the destination. It counts a person only
  if sec-fetch-mode is navigate or sec-fetch-dest is document, the accept
  header asks for HTML, and there's an accept-language. Anything else is
  counted as a fetcher. No IPs are kept.
- /me shows each post with its people and fetcher counts. Zero shows as 0,
  with one line on what is and isn't counted. It also has the bio link to
  copy, and Disconnect, which deletes the tokens, posts, counts and sessions.
- Privacy page: say there's one sign-in cookie, for the owner, and that
  metrics are read only if Buffer allows them.
- Known limit: KV counts are read-then-write, so two taps in the same second
  can come out as one. Fine at demo volume; a Durable Object if it matters.
